# Этап 11 — Публичный API

**Фаза:** 2 (Backend) · **Зависит от:** 10

## Цель
Публичные (read-only) эндпоинты, которыми фронтенд заменит моки, плюс приём заявок.

## Предусловия
- Модели и миграции готовы (этап 10), в БД есть сид-данные.

## Задачи

- [ ] Pydantic-схемы ответов — совпадают с TS-типами фронтенда (этап 04).
- [ ] CRUD-слой чтения (`crud/`).
- [ ] Публичные роутеры `api/public/`:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/categories` | список категорий |
| GET | `/api/categories/{slug}` | категория + её системы |
| GET | `/api/applications` | список применений |
| GET | `/api/applications/{slug}` | применение + подходящие системы |
| GET | `/api/products` | список (фильтры: `category`, `application`, `segment`, `popular`) |
| GET | `/api/products/{slug}` | система: изображения, цвета, характеристики, применения |
| GET | `/api/articles`, `/api/articles/{slug}` | новости |
| GET | `/api/projects` | портфолио |
| GET | `/api/banners` | активные баннеры главной |
| GET | `/api/contacts` | контактная информация |
| GET | `/api/configurator/options` | справочники конфигуратора — **только если по вопросу №1 выбран вариант «в БД»** |
| POST | `/api/leads` | приём заявки |

- [ ] **Локаль**: параметр `?lang=ru|tg|en|tr`. Значение по умолчанию — `ru`.
      Если перевод отсутствует — отдаём `null`, **не подставляя русский**:
      фолбэка в системе нет, фронтенд выводит пусто.
- [ ] Пагинация и сортировка где нужно (новости, портфолио).
- [ ] `POST /api/leads`:
  - валидация на границе (телефон, обязательные поля);
  - поля: имя, телефон, город, тип продукции, `scenario`
    (`calc` / `quote` / `dealer`), `payload` с составом конфигурации;
  - сохранение в БД;
  - ответ быстрый — фронтенд открывает WhatsApp **после** успешного ответа,
    поэтому долгая обработка здесь недопустима.
- [ ] Единый формат ошибок, корректные статусы, без «тихих» `catch`.
- [ ] Проверить OpenAPI-доки (`/docs`).

## Результат / артефакты
- Рабочий публичный API, задокументированный в `/docs`.

## Критерии готовности
- Все эндпоинты возвращают корректные данные из БД на всех четырёх локалях.
- `POST /leads` валидирует и сохраняет заявку, отвечает быстро.
- Ошибки обрабатываются явно и единообразно.

## Заметки
- Контракт ответов фиксируем строго — от него зависит этап 13.
- Telegram-уведомлений нет (решено): БД — архив истории, WhatsApp — рабочий канал.
