# Этап 12 — Админ-панель

**Фаза:** 2 (Backend) · **Зависит от:** 11

## Цель
Панель управления контентом с авторизацией. **2 пользователя, без ролей**
(бриф п.16.2 — «Сколько людей будет пользоваться админ-панелью: 2»).

Редактируемое: товары, категории, применения, новости, контакты, баннеры
главной + **просмотр заявок**.

## Предусловия
- Публичный API и модели готовы (этапы 10–11).

## Задачи

### Авторизация
- [ ] `POST /api/admin/login` — логин/пароль, выдача JWT.
- [ ] Хеширование пароля (`passlib`/bcrypt), проверка JWT в `deps.py`.
- [ ] Два пользователя, создаются сид-скриптом; пароли — из `.env`, не хардкодить.
- [ ] Защита всех админ-эндпоинтов JWT.

### CRUD-эндпоинты `api/admin/`
- [ ] **Товары** — create/update/delete, изображения, порядок, «популярный»,
      характеристики (гибкие пары), цвета, привязка к применениям.
- [ ] **Категории** — create/update/delete, порядок.
- [ ] **Применения** — create/update/delete, порядок, SEO-заголовок.
- [ ] **Новости** — create/update/delete, публикация/черновик.
- [ ] **Контакты** — редактирование.
- [ ] **Баннеры главной** — create/update/delete, порядок, активность.
- [ ] **Заявки** — **только чтение**: список, фильтр по дате и сценарию,
      просмотр состава конфигурации, экспорт.
      > Раздела «Заявки» не было в исходном плане — заявки писались в БД,
      > которую никто не открывает. Workflow не нужен: заявку разбирает человек
      > в WhatsApp, БД остаётся архивом истории.
- [ ] Загрузка изображений (локально или S3-совместимое хранилище).

### UI админки
- [ ] Раздел `app/admin/` во фронтенде Next.js — переиспользует стили и деплой.
- [ ] Страницы: логин, дашборд, списки + формы редактирования по разделам.
- [ ] **Мультиязычный ввод: все четыре локали (RU / TJ / EN / TR) обязательны.**
      Переводы делает исполнитель, поэтому обязательность ничего не блокирует,
      а данные всегда полны — что критично, так как фолбэка в системе нет.
- [ ] Табы или колонки по локалям в форме; индикатор заполненности у сущности.
- [ ] Загрузка изображений с предпросмотром.
- [ ] Замена временных фотографий на реальные — **без правок кода**. Все
      изображения сайта должны приходить из данных.

## Результат / артефакты
- Защищённые админ-эндпоинты + UI управления контентом.

## Критерии готовности
- Вход работает, неавторизованный доступ закрыт.
- Все разделы редактируются, изменения видны на публичном сайте.
- Нельзя сохранить сущность с незаполненной локалью.
- Заявки видны списком с составом конфигурации.

## Заметки
- 2 пользователя, роли не нужны — не усложнять.
- Пароли и `SECRET_KEY` — только через `.env`.
- Альтернатива UI — отдельная лёгкая SPA; рекомендуется всё же `/admin`
  в основном приложении.
