# Этап 04 — Каталог, категории и применения

**Фаза:** 1 (Frontend) · **Зависит от:** 03

## Цель
Каталог профильных систем (без цен), страницы двух категорий по материалу и
SEO-лендинги применений.

## Предусловия
- i18n-каркас готов (этап 03) — все новые страницы сразу мультиязычные.
- В `data/` описаны категории, применения и товары с типами.

## Структура — две оси

Товар = **профильная система**. Организация:

- **Категория** = материал: `pvc`, `aluminium` (2 записи). Это «дом» товара и его URL.
- **Применение** = фасет + отдельный SEO-лендинг. Связь с товаром — многие-ко-многим.

Причина: одна система (ROLLER) идёт и на окна, и на двери — положить её
в категорию «пластиковые окна» нельзя. При этом SEO-запросы из брифа п.14.2
(«пластиковые окна Душанбе», «алюминиевые двери Душанбе», «фасадное остекление»)
надо отрабатывать — этим занимаются лендинги применений.

### Применения (первичный список)
`windows`, `doors`, `sliding-systems`, `facade-glazing`, `mosquito-nets`,
`partitions`. Список уточняется вместе с контентом.

## Задачи

### Каталог `/[locale]/catalog`
- [ ] Заголовок, описание, сетка карточек систем.
- [ ] Фильтры: категория (ПВХ / алюминий), сегмент (эконом / средний /
      выше среднего / премиум), применение.
- [ ] Карточка: рендер, название, логотип бренда (если есть), сегмент, материал,
      2–3 ключевые характеристики, «Подробнее», CTA «Подобрать».
- [ ] Карточка обязана работать **без логотипа** (АЛД-45, ТЕРМО 60).

### Категория `/[locale]/catalog/[category]`
- [ ] Хлебные крошки, описание категории.
- [ ] Список систем категории.
- [ ] Слаги: **`pvc`**, **`aluminium`**.
      ⚠️ В старом плане фигурировал `pvh`, в коде — `pvc`. Единственно верный — `pvc`.

### Лендинги применений `/[locale]/solutions/[application]`
- [ ] Отдельная страница на применение: что это, какие системы подходят,
      контекстные изображения, FAQ-блок при наличии контента, CTA.
- [ ] Заголовок и текст затачиваются под SEO-запрос («Пластиковые окна в Душанбе»).
- [ ] Список систем формируется по связи «применение ↔ товар».

### Общее
- [ ] Переиспользуемые `ProductCard`, `CategoryCard`, `ApplicationCard`, фильтры.
- [ ] Пустые состояния, адаптив.
- [ ] Навигация: каталог → категория → товар; каталог → применение → товар.
- [ ] Обновить меню в шапке: пункты ведут на **лендинги применений**, а не на
      несуществующие категории.

## Модель данных (мок = будущий контракт API)

```ts
type Locale = 'ru' | 'tg' | 'en' | 'tr';
type I18n = Partial<Record<Locale, string>>;   // фолбэка нет: нет значения → пусто

type Category = { slug: 'pvc' | 'aluminium'; title: I18n; description: I18n; image: string };

type Application = { slug: string; title: I18n; description: I18n; image: string };

type Spec = { name: I18n; value: I18n };        // гибкие пары, не фиксированные колонки

type Product = {
  slug: string;
  name: string;                                  // латиница, не переводится
  kind: 'system' | 'component';
  categorySlug: Category['slug'];
  applicationSlugs: string[];
  segment: 'economy' | 'standard' | 'upper' | 'premium';
  shortDescription: I18n;
  description: I18n;
  specs: Spec[];
  colors: string[];
  images: string[];
  logo: string | null;                           // у алюминиевых брендов — null
  popular: boolean;
};
```

> **Почему `specs` — список пар, а не фиксированные колонки.** У москитной сетки,
> подоконника или ручки нет ни камер, ни стеклопакета. Гибкая схема принимает
> любой товар без миграций и позволяет заказчику самому заводить комплектующие
> через админку. Фильтры по брифу нужны только по категории и сегменту, так что
> типизированные колонки ничего не дают.
>
> ⚠️ Для **конфигуратора** (этап 06) этих пар недостаточно — ему нужны
> машиночитаемые справочники. Это открытый вопрос №1 в `00-overview.md`.

## Результат / артефакты
- `/catalog`, `/catalog/[category]`, `/solutions/[application]` на моках.
- Компоненты карточек и фильтров.

## Критерии готовности
- Навигация каталог ↔ категория ↔ применение ↔ товар работает.
- Карточка корректна и с логотипом, и без.
- Адаптив, единый стиль с главной, `build` / `lint` чистые.

## Заметки
- Цены не показываем — везде «Цена по расчёту» + CTA.
- Комплектующие (сетки, подоконники, кабель-каналы, шины, цилиндры) в каталог
  к запуску **не заводим** — контента по ним нет. Схема их принимает; заказчик
  добавит через админку, когда появятся фото и тексты.
