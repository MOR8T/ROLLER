## 1. О проекте

Корпоративный сайт-каталог **ROLLER.TJ** — производителя профильных систем
(ПВХ и алюминий) в Таджикистане.

**Цель сайта — информировать о продуктах.** Не продавать в один клик и не
собирать лиды любой ценой, а объяснить, что компания производит, чем бренды
отличаются и кому какой подходит.

**Слоган:** «Тепло и комфорт для каждого дома» / «Гармию осоиш ба хар як хонадон».

### Четыре аудитории

Сайт обслуживает их одновременно — это определяет и структуру, и визуальный язык.

| Аудитория | Вопрос | Целевое действие |
|---|---|---|
| Владельцы домов и квартир | «Какое окно мне подойдёт?» | Подобрать систему, вызвать замерщика |
| Застройщики, стройкомпании | «Потянете объём и сроки? Что уже строили?» | Запросить КП |
| Архитекторы, дизайнеры | «Какие системы, узлы, цвета, характеристики?» | Изучить систему, скачать материалы |
| Производители окон, дилеры | «Почём профиль оптом, какие условия?» | Прайс, дилерство |

Следствие: сайт не может быть только «человеческим» или только «техническим».
Разрезы профиля нужны — но не на первом экране. Подробности — `DESIGN.md` §1, §6.

### Фирменный стиль (брендбук, подтверждён)

- **Цвета:** чёрный `#1D1D1B` (rgb 29 29 27), красный `#D3001A` (rgb 211 0 26),
  белый `#FFFFFF`. Правило пропорций — `DESIGN.md` §3.
- **Шрифты:** `Chakra Petch` + `Montserrat` (брендбук стр. 07).
  ⚠️ **Chakra Petch не поддерживает кириллицу** — только `latin`, `latin-ext`,
  `thai`, `vietnamese`. Все кириллические заголовки де-факто отрисовываются
  Montserrat'ом. Подробности — `DESIGN.md` §4.

**Все шесть — самостоятельные бренды**, каждый со своей аудиторией. Линейка от
эконома к премиуму — ядро главной страницы.

| Бренд | Материал | Сегмент | Профиль | Камеры | Логотип |
|---|---|---|---|---|---|
| ЭКОЛАЙН | ПВХ | эконом | 60 мм | 3 | есть |
| ROLLER | ПВХ | средний | 60 мм | 4 | есть |

### Структура каталога

Товар = профильная система. Организация — **две оси**:

- **Категория** = материал: `pvc`, `aluminium` (2 записи). Это «дом» товара и его URL.
- **Применение** (`Application`) = фасет + SEO-лендинг: окна, двери, раздвижные
  системы, фасадное остекление, москитные сетки, перегородки. Связь с товаром —
  многие-ко-многим.

Причина: одна система (например ROLLER) идёт и на окна, и на двери — положить её
в категорию «пластиковые окна» нельзя, это ложь о предметной области. При этом
SEO-запросы («пластиковые окна Душанбе», «алюминиевые двери Душанбе») надо
отрабатывать — этим занимаются лендинги применений.

## 2. Технологический стек

| Слой | Технология | Заметки |
|---|---|---|
| Frontend | Next.js 16 (App Router) + React 19 | Инициализирован в `frontend/` |
| Стили | Tailwind CSS v4 | Настроен |
| Язык | TypeScript | strict |
| i18n | **`next-intl`**, 4 локали: `ru` / `tg` / `en` / `tr` | `localePrefix: 'always'`, слаги единые латинские |
| Анимация | CSS `animation-timeline: view()` для scroll-reveal; `framer-motion` — только интерактив | См. `DESIGN.md` §8 |
| Backend | FastAPI (Python) | Папка `backend/` пока пустая |
| ORM | SQLAlchemy 2.0 + Alembic | |
| БД | PostgreSQL | Мультиязычный контент — **JSONB-поля** |
| Валидация | Pydantic v2 | |
| Auth (админка) | JWT | **2 пользователя**, без ролей (бриф п.16.2) |

> ⚠️ `frontend/AGENTS.md`: установлен Next.js 16 — версия с ломающими изменениями.
> Сверяться с `frontend/node_modules/next/dist/docs/`, по библиотекам — context7
> MCP, а не по памяти. В частности: `middleware` переименован в **`proxy`**,
> `params` асинхронный, доступны типы `PageProps<'/[locale]'>` / `LayoutProps<…>`.

## 5. Функциональные требования

**Страницы:** Главная, Каталог, Категория, Применение (лендинг), Товар,
Конфигуратор, О компании, Портфолио, Новости/блог, Профессионалам, Контакты.

**Композиция главной** (по аудиториям, подробно — `DESIGN.md` §7):
Hero → Линейка брендов → Применения → Производство и масштаб → Объекты →
**Профессионалам** (тёмная секция) → Заявка → Контакты.

**Формы:** заявка с выбором сценария — «рассчитать» / «получить КП» /
«стать дилером». Поля: имя, телефон, город, тип продукции.
**Механика:** сабмит → `POST /api/leads` (**сохранение первым**) → после успешного
ответа открывается WhatsApp с подставленным текстом. БД — архив истории, WhatsApp —
рабочий канал; тип заявки разбирает человек.

**Конфигуратор** (вместо «простого калькулятора» из брифа): визуальный, по образцу
`imzo.uz/calculator`, **без показа цены**, результат — заявка. Подробности — этап 06.

**Цены:** не показываем нигде, только «цена по расчёту».

**Языки:** RU / TJ / EN / TR. Переводы делает исполнитель. Контент к запуску —
на всех четырёх языках.

**Админка:** 2 пользователя, без ролей. Редактируемое: товары, категории,
применения, новости, контакты, баннеры + **раздел «Заявки»** (просмотр истории).

**SEO:** базовая оптимизация. Ключи: «окна в Душанбе», «пластиковые окна Душанбе»,
«алюминиевые двери Душанбе», «фасадное остекление», «окна с установкой»,
«двери на заказ». Отрабатываются лендингами применений.

**Референсы:** IMZO (светлота, понятность), AKFA (спокойствие, масштаб) — как
ориентир, не копировать. Что берём и что не берём — `DESIGN.md` §2.

## 6. Соглашения по работе с планом

- Каждый файл этапа: **Цель**, **Предусловия**, **Задачи**, **Результат**,
  **Критерии готовности**, **Заметки**.
- Выполненные пункты — `- [x]`.
- Не переходить к следующей фазе без выполнения критериев готовности предыдущей.
- Этап 02 — **точка утверждения**: без «ОК» заказчика этапы 03+ не запускаем.
- Перед версткой — читать `frontend/DESIGN.md`. Перед кодом на Next — читать
  `frontend/node_modules/next/dist/docs/`.

### Общие принципы

- Mobile-first, адаптивность обязательна.
- A11y: семантика, `alt`, контраст WCAG AA, видимый `focus-visible`.
- Производительность: `next/image`, AVIF/WebP, оптимизация шрифтов, Core Web Vitals.
- Дизайн-токены вместо «магических» значений.
- Моковые типы = будущий контракт API.
- Ошибки обрабатываются явно, без «тихих» `catch`.
