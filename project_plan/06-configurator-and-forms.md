# Этап 06 — Конфигуратор и формы заявок

**Фаза:** 1 (Frontend) · **Зависит от:** 02 (формы-заглушки), 04 (данные систем)

## Цель
Визуальный конфигуратор конструкции и единый механизм отправки заявок.

## Важно: это не «калькулятор цены»

В брифе п.2.1 заказчик просит «калькулятор расчёта стоимости», а в п.5.3
запрещает показывать цены. Противоречие разрешается так же, как у референса
`imzo.uz/calculator`: **конфигуратор даёт ощущение расчёта, но цену не показывает** —
финал это заявка. Проверено: у imzo на последнем шаге кнопка «Отправить», цены
нет нигде.

Дополнительно: окна считаются по м², а в брифе п.8.3 параметр «размеры» не
отмечен — построить настоящий калькулятор на заявленных параметрах в принципе
невозможно. Размеры в конфигуратор добавляем: замерщику они всё равно нужны,
и заявка становится в разы полезнее отделу продаж.

## Задачи

### Конфигуратор `/[locale]/configurator`

- [x] Табы **Окно / Дверь**.
- [x] **Окно** — 1 / 2 / 3 створки, **у каждой створки тип открывания**:
      глухая / поворотная / поворотно-откидная. Значки на схеме.
      (По брифу у систем есть «откидной механизм и обычный».)
- [x] **Дверь** — одностворчатая / двустворчатая / с фрамугой.
- [x] **Размеры** — два слайдера (ширина, высота) в мм, с числовым вводом.
- [x] **Живое превью — параметрический SVG.** Рамы и створки рисуются вектором,
      цвет — заливка. Любое число створок, любые пропорции, мгновенная
      отрисовка, лёгкий на мобильных.
      > Фотореалистичное превью из имеющихся файлов собрать нельзя: в `notes/`
      > все 188 рендеров — **одностворчатые**. Двух- и трёхстворчатых, а также
      > дверей нет вообще.
      > **Возможный апгрейд:** SVG-геометрия + текстура ламинации, нарезанная
      > из существующих PNG (~7 плиток для ПВХ + 4 для алюминия). Делать вторым
      > проходом, если останется время.
- [x] **Параметры:** тип профиля (ПВХ / алюминий) → серия (6 систем) →
      стеклопакет → цвет ламинации → комплектующие (подоконник, москитная сетка) →
      количество штук.
- [x] **Каскад зависимостей:** выбор материала ограничивает серии; серия
      ограничивает стеклопакеты, цвета и типы открывания. **ЭКОЛАЙН — только белый.**
- [x] **«Добавить ещё»** — несколько позиций в одной заявке.
- [x] Финал — **«Отправить»**, никакой цены.

> ⚠️ **Открытый вопрос №1** (`00-overview.md`): откуда конфигуратор берёт списки
> опций. Гибкие пары `specs` из этапа 04 для этого не годятся — они текстовые.
> Нужны либо структурированные справочники в БД (`Color`, `GlazingOption`,
> `OpeningType` + привязки к системам), либо хардкод во фронтенде.
> **Решить до этапа 10.** На фронт-фазе списки живут в `data/` как моки, но
> их форма должна заранее быть машиночитаемой, а не текстовой.

> ⚠️ Нет данных: бренд и цвета фурнитуры, «отлив», смысл параметра «монтаж»
> из брифа п.8.3. Эти поля не ставим, пока заказчик не ответит (вопрос №4).

### Формы заявок

- [x] Общий компонент `RequestForm`, **три сценария**: «Рассчитать» /
      «Получить КП» / «Стать дилером». Поля: имя, телефон, город,
      тип продукции, комментарий.
- [x] Валидация на границе: телефон, обязательные поля, без «тихих» ошибок.
- [x] **Порядок отправки — строго такой:**
      1. `submitLead()` → `POST /api/leads` — **заявка сохраняется первой**;
      2. только после успешного ответа открывается
         `https://wa.me/992700600700?text=…` с подставленным текстом.
      > Если делать наоборот, заявка теряется молча: посетитель, не дожавший
      > «Отправить» в WhatsApp, исчезает бесследно, а заказчик об этом не узнает.
- [x] На фронт-фазе `submitLead()` — заглушка с тем же интерфейсом; реальный
      вызов подключается на этапе 13 без переписывания форм.
- [x] Тип сценария передаётся и в БД, и в текст WhatsApp-сообщения.
      **Разбирает заявку человек** — отдельного workflow в админке не нужно.
- [x] Состояния: загрузка, успех, ошибка — явно.

## Результат / артефакты
- Страница конфигуратора с SVG-превью, `RequestForm`, утилита wa.me-ссылки.

## Критерии готовности
- Конфигуратор собирает конструкцию, превью соответствует выбору.
- Каскад зависимостей корректен (ЭКОЛАЙН не предлагает цветных вариантов).
- Заявка уходит в правильном порядке: сохранение → WhatsApp.
- Адаптив (слайдеры и SVG на мобильном), `build` / `lint` чистые.

## Заметки
- CTA конфигуратора присутствует на карточках систем и на странице товара.
- ~~Пункт меню называется «Конфигуратор» ... **не «Калькулятор»**~~ —
  **решение заказчика: пункт называется «Калькулятор», маршрут `/calculator`.**
  Возражение плана остаётся в силе на уровне контента: слово обещает цифру,
  поэтому на странице дважды сказано, что цену считает менеджер, а не сайт.
