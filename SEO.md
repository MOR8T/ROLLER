# SEO ROLLER.TJ

Что настроено, где это лежит и что ещё нужно от клиента.

Всё, что настраивается, находится в **одном файле** — [`frontend/lib/seo-config.ts`](frontend/lib/seo-config.ts).
Отдельного раздела в админ-панели нет: эти значения меняются раз в несколько
месяцев, и правка файла с последующим деплоем надёжнее формы, которую нужно
держать в синхронизации с кодом.

---

## 1. Что нужно от клиента

Пока не заполнено. Каждый пункт — одна строка в `seo-config.ts`; сайт работает
и без них, просто соответствующий тег не выводится.

| Что | Где взять | Куда вписать |
|---|---|---|
| Код подтверждения Google | Search Console → «Способ подтверждения» → «HTML-тег» | `verification.google` |
| Код подтверждения Яндекса | Вебмастер → «Настройки» → «Права доступа» → «Мета-тег» | `verification.yandex` |
| Номер счётчика Метрики | Метрика → «Настройки» → номер вида `98765432` | `analytics.yandexMetrika` |
| Идентификатор GA4 | GA4 → «Потоки данных» → `G-XXXXXXXXXX` | `analytics.googleAnalytics` |
| Юридическое название | у клиента | `organization.legalName` |
| Улица и дом, город, индекс | у клиента | `organization.streetAddress`, `.locality`, `.postalCode` |
| Координаты | Яндекс.Карты → правой кнопкой по точке → «Что здесь?» | `organization.latitude`, `.longitude` |
| Часы работы | у клиента | `organization.openingHours`, формат `Mo-Sa 08:00-18:00` |
| Баннер 1200×630 | у клиента | положить в `frontend/public/og/`, путь в `ogImage` |

Вписывать **только сам код**, а не тег целиком — например
`verification.google: "ABC123token"`, не `<meta name="..." content="ABC123token" />`.

Отдельно стоит определиться со списком приоритетных запросов («окна ПВХ
Душанбе», «алюминиевые фасадные системы» и т.д.). Сейчас заголовки и описания
взяты из текущих текстов сайта — это разумная отправная точка, но не
позиционирование, согласованное с клиентом.

### Как вписать

```bash
# 1. открыть файл
frontend/lib/seo-config.ts

# 2. заменить пустые строки на значения, сохранить

# 3. проверить, что собирается
cd frontend && npm run build

# 4. закоммитить и выкатить (см. DEPLOYMENT.md)
```

Изменения попадают на сайт только после пересборки фронтенда: значения
подставляются на этапе сборки, а не читаются на каждый запрос.

## 2. Что уже настроено

### Домен и canonical
`seoConfig.siteUrl = "https://roller.tj"`. Из него собираются `metadataBase`,
все canonical, `sitemap.xml`, `robots.txt` и абсолютные ссылки в разметке.
На каждой странице есть `<link rel="canonical">` на её собственный адрес с
языковым префиксом.

### Четыре языка (hreflang)
Каждая страница объявляет все четыре версии себя плюс `x-default` на русскую.

⚠️ **`tj` в адресе, но `tg` в теге.** Сегмент URL остаётся `/tj` — так
зафиксировано в `i18n/routing.ts`. Но `tj` — это код *страны* по ISO 3166, а код
*языка* по ISO 639 — `tg`. При невалидном теге Google отбрасывает весь кластер
альтернатив целиком, а не одну строку, поэтому в `hreflang`, `<html lang>`,
`og:locale` и `inLanguage` выводится `tg` / `tg-TJ` / `tg_TJ`.

### sitemap.xml
`https://roller.tj/sitemap.xml` — генерируется автоматически: шесть статических
страниц, все категории, все товары и все новости, каждая в четырёх языках, с
перекрёстными ссылками `xhtml:link`. Товар, добавленный в админ-панели,
попадает туда сам, без пересборки.

### robots.txt
`https://roller.tj/robots.txt` — закрывает `/admin`, `/login`, `/api/` и
постраничную навигацию `?page=`, указывает адрес sitemap и канонический хост
для Яндекса.

### Превью ссылок (Open Graph)
Заголовок, описание, адрес, язык и картинка — для WhatsApp, Telegram, Facebook.
У товара подставляется его фото, у новости — её обложка, у остальных страниц
общая картинка из `ogImage` (пока не загружена).

### Разметка для поисковиков (JSON-LD)
- `LocalBusiness` + `WebSite` — на каждой странице, из контактов и соцсетей
  админ-панели плюс данных организации из конфига;
- `BreadcrumbList` — на странице категории и на странице новости;
- `Product` — на странице товара;
- `NewsArticle` — на странице новости.

⚠️ **Цен в разметке нет и быть не должно.** У `Product` нет ни `offers`, ни
`priceRange`, ни рейтингов: сайт цен не публикует, калькулятор — не
прайс-калькулятор, а выдуманный блок цены это прямой штраф за
структурированные данные. Из-за этого Google не покажет расширенный сниппет
товара — для каталога производителя без интернет-магазина это правильный исход.

### Счётчики
Метрика и GA4 подключаются только при заполненном номере. Пустое поле — скрипт
не грузится вообще, никаких сторонних запросов со страницы не уходит.

## 3. Как что-то временно закрыть от поиска

| Задача | Что сделать |
|---|---|
| Убрать весь сайт из поиска | `seoConfig.allowIndexing = false` — все страницы получают `noindex`, `robots.txt` закрывает обход, `sitemap.xml` пустеет |
| Убрать одну страницу | добавить её ключ в `seoConfig.noindexPages`, например `["calculator"]` |
| Закрыть сайт от посетителей | админ-панель → «Настройки сайта» → «Сайт в разработке» (заодно ставит `noindex`) |

Первое и третье — разные вещи: `allowIndexing` прячет сайт только от
поисковиков, «Сайт в разработке» — от людей.

## 4. Где что лежит в коде

| Файл | Отвечает за |
|---|---|
| `frontend/lib/seo-config.ts` | **все настройки** — единственный файл, который правят |
| `frontend/lib/seo.ts` | адреса, hreflang, `alternates` |
| `frontend/lib/page-metadata.ts` | сборка `<head>` страницы; через него идут **все** `generateMetadata` |
| `frontend/lib/json-ld.ts` | разметка schema.org |
| `frontend/app/sitemap.ts` | `sitemap.xml` |
| `frontend/app/robots.ts` | `robots.txt` |
| `frontend/components/seo/analytics.tsx` | Метрика и GA4 |
| `frontend/messages/*.json` | заголовки и описания страниц (`metaTitle`, `metaDescription`) |

**Заголовки и описания страниц лежат не в конфиге, а в каталогах сообщений** —
там же, где весь остальной текст сайта, по правилу из `CLAUDE.md`: структура в
коде, текст в `messages/`. Чтобы поменять `<title>` раздела «О компании»,
правится `about.metaTitle` во всех четырёх файлах `messages/`.

У товаров, категорий и новостей заголовок и описание берутся из самой карточки
в админ-панели — отдельного места для их метаданных нет намеренно, иначе две
копии одного названия рано или поздно разойдутся.

## 5. Что стоит сделать дальше

1. **Хлебные крошки на странице товара.** Это единственная страница без видимой
   навигационной цепочки, поэтому на ней нет и разметки `BreadcrumbList` —
   разметка без видимого аналога считается несоответствием. Появятся крошки —
   подключится и разметка.
2. **Подать sitemap** в Search Console и Вебмастер после подтверждения прав.
3. **Проверить разметку** после заполнения данных организации:
   [validator.schema.org](https://validator.schema.org/) и
   [Яндекс.Валидатор](https://webmaster.yandex.ru/tools/microtest/).
4. **Поправить контакты**: в базе у телефона, email и ссылки на карту в конце
   лишний дефис (`+992 700 600 700-`) — он попадает в разметку организации как
   есть. Правится в админ-панели → «Контакты».
